# azionapi-rust-sdk

Official Azion SDK for the Rust programming language.

The repository contains one crate per Azion API product. Every crate is
generated by [OpenAPI Generator](https://openapi-generator.tech) from the
product's OpenAPI document and is self-contained: it has its own
`Cargo.toml`, API reference (`docs/`) and README. The API functions are
`async` and use [reqwest](https://crates.io/crates/reqwest) as HTTP client.

## Installation

The crates are not published to crates.io. Add the crate you need as a git
dependency and pin a release tag:

```toml
[dependencies]
personal_tokens = { git = "https://github.com/aziontech/azionapi-rust-sdk", tag = "v0.80.0" }
tokio = { version = "1", features = ["macros", "rt-multi-thread"] }
```

## Usage

All crates follow the same pattern: build a `Configuration`, set the API
token and call the async function of the API module. For example, with
`personal_tokens`:

```rust
use personal_tokens::apis::{configuration::{ApiKey, Configuration}, personal_token_api};

#[tokio::main]
async fn main() {
    let mut configuration = Configuration::new();
    configuration.api_key = Some(ApiKey {
        prefix: Some("Token".to_owned()),
        key: "YOUR_API_TOKEN".to_owned(),
    });

    match personal_token_api::list_personal_token(&configuration).await {
        Ok(tokens) => println!("{:?}", tokens),
        Err(error) => eprintln!("request failed: {}", error),
    }
}
```

## Development

The crate directories are generated code. They are updated by automated
`generated-sdk` pull requests ("Auto-Generated SDK" commits), so do not edit
them by hand: changes belong in the OpenAPI documents or generator settings.
Repository-level files (tests, workflows, documentation) are maintained here.

Run the functional tests (Node.js 22 and a Rust toolchain required):

```sh
cd tests/vitest
npm ci
npm test
```

The suite builds a small harness crate (`tests/vitest/harness`) that
depends on every crate, so a crate that no longer compiles fails the build.
It also checks that each endpoint documented in a crate README exists as a
public function, and calls endpoints of several crates against a local HTTP
double to verify routing, path parameters, token authentication and response
deserialization.

Linting: `cargo clippy` on the harness workspace (correctness lints) and
ShellCheck on the `git_push.sh` scripts.

## Versioning

Every merge to `main` is tagged with the next SemVer version (`vX.Y.Z`)
by `.github/workflows/bump_version.yml`. See [CHANGELOG.md](CHANGELOG.md).
